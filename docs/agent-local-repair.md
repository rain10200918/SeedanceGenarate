# Agent 局部故障修复

本功能用于**尚未提交视频任务的准备失败**。它不是通用自动修复，也不会自动重买失败的视频。

## 用户流程

1. Agent 在分镜或视频准备阶段遇到模型不可用、时长不支持、参考不兼容等可信故障，保留进度并暂停。
2. 在 Agent 页的进度面板查看「修复建议」。服务端读取当前开放模型和本人有效的图片作品版本，筛选仍满足原时长、画幅及参考角色的方案。读取建议不会调用生成模型。
3. 用户检查目标步骤或幕号、来源版本、影响范围和候选规格，手动选择方案。没有适合的模型或参考时显示原因，不擅自缩短视频或转为无参考生成。
4. 点击「采用修复并重新准备」。服务端再次验证版本、故障和候选有效性，保存独立的修复绑定，恢复原准备链。
5. 准备完成后仍进入原费用确认流程。**采用修复不是批准费用**；只有明确批准新的报价后才进入视频提交。

已成功的图片、视频和旧任务不被改写。单幕修复只覆盖准确目标规格；检查点仍按完整输入绑定匹配，因此同一批尚未完成的提示词可能需要重新准备，不保证所有旧提示词都能复用。

## 失败与重试

- 页面断线、正在提交或有未决请求时，不能采用新修复。
- 请求发送前先保存请求身份；浏览器存储失败则不发送。
- 网络失败或结果未知：保留原请求，刷新后使用「重试原请求」，不自动创建新身份。
- 建议失效或工作区冲突：刷新状态与建议，清除原选择；用户重新检查和选择，不自动确认新方案。
- 已提交、受理未知或已发生付费任务的失败，不通过该入口重新提交。必须沿用原任务的查询与恢复边界。
- 老的暂停记录若没有可信、准确的准备失败绑定，不会凭报错文案猜出修复目标；页面可能没有可采用的建议。

## 接口与上线边界

- `GET /api/agent/conversations/{id}/repairs`：只读建议，最多12项。
- `POST /api/agent/conversations/{id}/repairs`：仅接受 `clientActionId`、`expectedWorkspaceVersion`、`failureId`、`optionId`。客户端不能提交任意执行规格。
- 同一个请求身份与正文重复到达不会重复创建修复；同身份不同正文被拒绝。
- 新增 Flyway 迁移 `V56__agent_local_repair.sql`，存储已确认的局部修复绑定；不修改钱包和原任务表。

发布时需要后端迁移和接口先就绪，再发布相应前端。本轮开发不会自动迁移生产数据库、重启服务或提交真实收费生成。真实 MySQL 多实例竞争、云存储和上游模型能力仍需在获授权后另行验证。
