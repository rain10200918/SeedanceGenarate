# Agent 整组报价过期后恢复

当提示词已准备完成、整组费用报价过期时，未提交过任何任务的当前批次可以显式申请“重新核价”。重新核价不是批准生成：新卡片可能有新价格，必须审阅并再次确认费用。

恢复顺序：过期卡 → 重新核价 → 复核本人会话、计划与分镜准确版本、模型/参数/参考、原提示词完整准备绑定 → 新报价卡 → 明确确认 → 原有逐幕生成与完成屏障。

- 旧报价和旧审批仍然失效，不复活、不覆盖。新建父调用、子审批与批次身份，原计划保留。
- 视频仅复用原父调用的全部成功检查点；校验模板、协议、规格与正文，不重新调用模型。v3/v4不混用。新报价到期后可再次申请同样的严格复验。
- 任一任务已提交（含领域中有记录而Agent尚未回填）、关联Task、部分失败、拒绝、取消、当前计划改变，均不进入此恢复路径。
- 绑定变化或检查点缺失时返回409，必须到分镜作品卡重新准备；不能为了恢复而缩短视频、删参考或绕过费用确认。
- 网络失败支持使用原请求编号重试。读取快照不核价、不生成；并发请求只能建立一份新报价。

接口：`POST /api/agent/conversations/{id}/approval-grants/{grantId}/requote`，仅接受`clientActionId`、`expectedVersion`、`bindingHash`。返回当前Snapshot。旧报价卡新增可选`canRequote`、`requoteReason`，只是申请资格提示，POST仍做最终复验。未支持这些字段的旧前端不会显示恢复入口。

本次代码需要发布后端与前端才对线上生效，不需要新增数据库迁移；本地测试不代表线上会话已恢复或真实GPU生成已验证。本轮不修改线上历史、不部署、不提交真实任务。
