# 平台导演技能

## 使用

Agent → 技能 → 导演技能模板 → 选择模板 → 复制为我的草稿 → 查看规则预览 → 确认并发布新版本 → 在当前对话使用。

首次导入的规则已由平台整理并校验，不消耗一次LLM解析。修改正文后需保存草稿、重新解析并确认发布。初次导入不是自动发布或自动运行；使用后沿现有持久化Recipe/Plan执行。

| 模板 | 自动产出 |
| --- | --- |
| 漫剧导演 | 故事/角色设定 → 完整剧本 → 连续分镜 |
| 小说改编导演 | 改编脚本 → 短剧分镜 |
| 萌宠寓言导演 | 幼儿寓言脚本 → 动画分镜 |
| 商品广告导演 | 广告创意/脚本 → 广告分镜 |
| 校园宣传片导演 | 基于提供资料的脚本 → 宣传片分镜 |
| 角色场景设定师 | 角色、场景与风格文字母版 |
| 分镜连续性审稿 | 有证据位置的文本问题及局部修订建议 |
| 视觉提示词导演 | 逐镜静态/动态提示词 |
| 九宫格分镜策划 | 九拍故事 → 九幕分镜文字 |

## 真实能力边界

这些模板不替换原子Skill或底层模型。当前模板运行阶段仅使用script-generation、storyboard-generation、prompt-optimization。分镜完成后，用户可从已有分镜作品操作启动逐幕参考图/视频计划；媒体生成仍需原费用审批，不是这个文字Recipe自动提交视频。

角色设定和连续性检查能减少文字规格漂移，不能保证生成模型保持同一张脸。使用真实角色图片时仍需准确版本引用、支持参考图的模型，以及对真实产物进行检查。没有真实视觉观察时不声称已识别图片；本批没有新增视觉理解能力。配音、音乐、自动合成、视频视觉QA和九宫格图片拼版均未在本批接入。资料查证仍用已有平台研究能力，不伪造外部资料。

## 存储和升级

- 模板只来自固定classpath JSON，不允许用户传入执行脚本或任意远程模板地址。
- 导入请求绑定templateId/version/hash和clientActionId。同一用户重复提交同一请求返回同一草稿；同key更换规格被拒绝。
- 私有草稿存creative_recipe，预览存compilation_json；确认发布使用既有creative_recipe_version，不新增表。
- 模板更新需要提高version，hash覆盖名称、内容、规则、来源和限制。已有发布版本与正在执行的Recipe不随资源变化。
- 模板目录无法读取时私人技能仍可管理，导入未知结果沿原请求重试。
- 来源和MIT声明见[来源许可](agent-director-templates-NOTICES.md)，同一许可声明也随后端JAR打包。

## 验证范围

本地单元/集成测试使用mock模型；浏览器验证使用拦截API。它们证明规则、导入、发布及状态流转，不证明真实LLM创作质量、图片理解、GPU生成或最终成片效果。上线不需要本次数据库迁移，需要更新后端资源和前端构建。
