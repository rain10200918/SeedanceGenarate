# Agent 视频提示词准备协议

## 第二轮：精简指导与确定性组装

流程：确认分镜与规格 → 按原规则报价 → 选择准备协议和逐幕字符额度 → 一幕一个作业调用文字模型 → 严格校验内容字段 → 后端组装目标模型格式并校验完整台词 → 保存当前幕检查点 → 全部准备通过 → 原费用确认 → 按已确认的提示词提交媒体任务。

新准备绑定使用 `video-prompt-fields-v4`。文字模型填写 `items[].key` 和 `items[].sections`，不自行拼顶层标题。后端根据已审核的打包模板输出固定标题、顺序和适用的首帧对齐前缀；实际参考图和角色只来自原生成参数，不增加新的参考能力。未知模板或整份指导指纹变化时沿用v3，不静默丢弃自定义规则。

单幕最终提交上限仍为4000字符，全批仍为16000字符，最多12幕；这是当前平台的提交边界，不代表上游模型物理上限。先为模板格式、完整旁白/对白及视觉描述预留空间，再按源分镜复杂度分配剩余额度。无法容纳完整原文时调用模型前明确失败，不删台词、不改时长。字符额度与文字模型输出token额度不同，后者仍使用第一轮的独立配置。

## 检查点与升级

- 旧 `video-prompt-scenes-v3` 的模板、hash计算、均分额度和响应格式保持原样。当前调用优先；显式恢复同一session、epoch、计划步骤与精确输入绑定的未审批旧任务时，继续v3并原样复用成功幕。
- 没有匹配旧绑定的新任务才使用v4；v4 hash覆盖旧输入绑定、协议版本、实际精简指导及每幕额度。修改源作品版本、模型、参考、总目标、时长等仍会改变绑定。
- 原调用不允许中途换协议或覆盖已成功检查点。不同协议/绑定、已审批、已取消和旧epoch不能混用。升级不主动恢复暂停任务，不重写已确认的提示词。
- 已有旧任务不会自动获得新额度和精简指导；若要启用新协议，应在新的创作任务中重新开始准备，而不是删除或篡改旧检查点。
- 原逐幕作业、租约/取消守卫及费用确认不变；格式修复仍一次，当前幕截断仍一次且共用原三次总尝试。不增加媒体重投、模型切换、并行生成或通用上下文压缩。

新协议格式错误使用 `STRUCTURED_ITEM_SHAPE` / `STRUCTURED_SECTIONS` 等安全诊断码。运行日志记录 `protocol`、`promptCharLimit` 和原调用/幕次身份，不记录模型原文或密钥。修改已审核模板的语义需同步审查codec及指导指纹；修改组装协议的含义需升级协议版本，不原地重解释存量检查点。

引用标签硬校验仅用于 `subject_definitions` / `retention_analysis` 等专门的引用元数据；自由正文可能包含对白或字幕的尖括号字面量，不据此增删实际参考输入。正文是否完全符合创作意图仍属于模型质量验证，不把关键词扫描当作语义正确性保证。

## 验证边界

本地验证使用H2和假文字模型，不向线上数据库写入，不提交付费视频任务。真实上游模型对新字段协议的服从率、生成质量、实际token额度支持和MySQL多实例锁行为，仍需部署后的独立联调。此轮不需要数据库迁移，需更新后端后新协议才生效。
